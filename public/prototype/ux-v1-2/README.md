# REPENT — HTML UX Validation Prototype (ux-v1-2)

**상태: NON-CANONICAL / UX VALIDATION ONLY / OWNER REVIEW용**

Owner UX 개편안을 브라우저에서 실제로 눌러보며 검증하기 위한 HTML 프로토타입이다.
구현 산출물이 아니다.

- Canonical Product Meaning은 여전히 `docs/final/01~10`이다.
- Final Documentation을 대체하지 않고, Figma Visual Lock을 교체하지 않는다.
- Production App(`app/`, `src/`)은 이 프로토타입을 근거로 수정하지 않는다.
- Owner PASS 전에는 어떤 내용도 Canonical로 승격하지 않는다.

## 위치가 `public/` 아래인 이유

Next.js는 `public/`만 정적 파일로 서빙한다. Preview URL을 확보하려면 이 경로여야
하며, 경로 안에 `prototype/ux-v1-2`를 그대로 유지했다. Production 라우트(`app/`)와
도메인 코드(`src/`)에는 연결되지 않는다.

## 검증 대상 Owner UX Delta (모두 CANDIDATE)

1. Main Nav 5개 — 여정 / 기도 / 약속 / 회개 / 고백 (실행 독립 탭 제거)
2. Action은 Promise 상세 안에서 추가·관리
3. **First Entry = 코치마크 투어** — 앱 홈 위에 반투명 안내가 7단계로 뜨고,
   눌러보며 익힌 뒤 기도 남기기로 연결. **3개 질문은 제거**
4. **인생 그래프** — 좌우 스크롤 생애 타임라인, 사건 점을 곡선으로 연결.
   아래에 사건 목록, 누르면 `그날의 생각` / `지금 돌아보면`.
   예시는 40세 여성 기준 13개 사건
5. **터닝포인트의 의미를 화면에 명시** — 인생 그래프에 큰 점으로 남길 시기를
   본인이 표시하는 기능이라고 설명 배너로 안내
6. **기도 = 묶음 구조** — 영혼을 위한 중보 / 가족 / 건강 / 재정과 일 /
   교회와 사역 / 나 자신. 묶음 → 제목 목록 → 제목 상세
7. **기도 제목 상세의 세 가지 마음** — 하나님께 드리고 싶은 마음 /
   받고 싶은 마음 / 천국에서 듣고 싶은 칭찬
8. **분별 프롬프트** — "내가 원하는 결과를 얻으려는 마음인지, 하나님께서
   기뻐하실 일을 구하는 마음인지" 스스로 묻는 자리. 묶음별로 질문이 다르다
9. **기도로 그치지 않았는지** — 기도 상세 하단에 그 기도에서 이어진 약속과
   실행 횟수·최근 날짜를 표시
10. Repentance 4영역 — 죄를 돌아보기 / 구체적으로 돌아보기 /
    새롭게 깨달은 것(선택) / 돌이키기 + 선택 말씀·약속·실행
11. **고백 Feed 확장** — 아바타 + 넓은 본문(16.5px) + 종류 태그 + 공감 1종,
    상단 `전체 / 내 기록` 세그먼트, 컴포저는 피드 상단의 한 줄

## Cross-Flow Continuity

모든 화면이 **Entry Context / Next Optional Action / Return Target** 셋을 갖는다.

| 연결 | 방식 |
|---|---|
| 기도 → 약속 | 저장 후 브릿지. `여기서 마치기`도 동등하게 제공 |
| 기도 제목 → 약속 | 상세에서 `이 기도를 약속으로 남기기` |
| 약속 → 실행 | 약속 상세 안에서 바로 입력, 실행은 약속의 하위 기록 |
| 실행 → 돌아보기 | 저장 직후 `오늘 이 약속을 어떻게 살아냈나요?` |
| 돌아보기 → 회개 | 4개 선택지 중 하나. 자동 전환 없음 |
| 회개 → 고백 | 마친 뒤 `일부만 골라 나누기`. 자동 공유 없음 |
| 모든 기록 → 여정 | 저장 시 토스트로 `여정에 남았어요 · 여정에서 보기` |
| Return Contract | 이어서 들어온 화면 상단에 출처 유지, 저장 후 원래 맥락으로 복귀 |

## 유지된 Product Lock

Prayer Response Tracking 없음(묶음은 분류일 뿐 상태가 아니고, 상단 숫자는 단순
기록 수) · Action Failure ≠ Sin · Failure Cause 질문 없음 · Auto Repent 없음 ·
Repentance Fixed Step / Progress % / Score 없음 · `회개 완료` 문구 없음
(Final CTA는 `회개 기록 마치기`) · Faith / Spiritual Score 없음 · 익명 게시 없음
(공개 범위 3옵션) · 공감 수로 줄 세우지 않음 · Missing Day = No Point, 기록 마커
레이어에 보간 없음.

**분별 프롬프트는 판정이 아니다.** 질문만 제시하고, 화면에 "앱과 AI는 이 기도가
옳은지 그른지, 욕심인지 아닌지 판단하지 않습니다"를 명시했다.

## ⚠️ Canonical Lock과 충돌하는 CANDIDATE

Owner가 직접 지시한 항목 중 현재 Canonical과 충돌하는 것들이다.
Owner PASS 전까지 `docs/final/*`는 그대로 두며, 아래를 판단 대상으로 올린다.

| 항목 | Canonical | 이 프로토타입 |
|---|---|---|
| 인생 그래프의 선 | `05` Interpolation 금지, 성장 그래프처럼 보이게 금지 | 생애 사건 점을 곡선으로 연결 |
| Main Nav | `여정 / 약속 / 실행 / 회개 / 고백` | `여정 / 기도 / 약속 / 회개 / 고백` |
| Onboarding | `SCR-RPT-ONB-001` 가입 직후 3개 선택 질문 | 3개 질문 제거, 코치마크 투어로 대체 |
| Repentance 구성 | Optional Progressive Flow, Fixed Step 금지 | 4개 영역 (번호·진행률은 노출하지 않음) |

인생 그래프에 둔 방어선:

- y축에 **수치·눈금·점수 라벨이 없다.** 높낮이는 사용자가 직접 표시한 `그때의 마음`.
- 화면에 "신앙의 수준이나 점수가 아니며, 앱이 판단하지 않습니다"를 명시.
- 선으로 잇는 것은 **생애 사건 레이어**뿐. 기도·회개 등 **기록 마커는 여전히 점만**
  찍고 보간하지 않는다(별도 영역).
- 사건과 높낮이는 전부 사용자 입력이며 AI가 생성하거나 평가하지 않는다.
